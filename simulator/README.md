# Симулятор датчиков СМВУ и учебный контур

Симулятор изображает полевую систему (СМВУ). Он хранит состояние каждого канала и отправляет в Kafka
сообщения в том же формате, что и адаптер журналов заказчика: те же строки значений («Обнаружен дым»,
«Не замкнут», «Обесточен»), тот же флаг «тревожное», тот же ключ канала. Поэтому платформа обрабатывает
его поток так же, как боевой: те же профили нормализации, эпизоды, сценарии риска, эскалация.

## Контуры

```
Полевой контур (сеть field)
  simulator, веб :8095  ──►  Kafka: smvu.training-events

Учебный контур
  Kafka  ──►  consumer-training  ──►  БД collector_training
  backend-training, worker-training  ──►  https://localhost/training/

Рабочий контур (в эксплуатации поток даёт шлюз СМВУ)
  Kafka: smvu.raw-events  ──►  consumer  ──►  БД collector
  backend, worker  ──►  https://localhost
```

- **Полевой контур.** Симулятор подключён к отдельной сети `field`, где из платформы есть только брокер Kafka.
  База, Redis и бэкенды из симулятора даже не разрешаются по имени. Веб-интерфейс симулятора открыт
  только на `127.0.0.1`.
- **Учебный контур** — тот же образ платформы, но своё окружение:

  | Ресурс | Учебный контур |
  |---|---|
  | База | `collector_training` на том же сервере PostgreSQL |
  | Redis | индекс `1` |
  | Тема Kafka | `smvu.training-events` |
  | Help desk | свой экземпляр mock help desk |
  | Адрес | https://localhost/training/ — подсистема на том же адресе, вход общий с рабочим контуром |

  Вместо справочников заказчика в учебный контур смонтирован полигон. Модели там не переобучаются,
  погода не загружается.
- **Учётные записи** общие: токен выдаёт рабочий контур, учебный читает учётки, роли и команды из его
  базы (docs/platform.md). Своего входа у учебного контура нет. Команды получают зоны на полигоне,
  потому что у объектов полигона те же названия (Мю, Кси, Тау).

## Учебный полигон

Полигон — это `polygon/dataset/справочник_объектов_диспетчер.csv` и `справочник_каналов_датчиков.csv`
в формате заказчика. Их читают и симулятор (как каталог устройств), и платформа (штатным импортом
справочников), поэтому полигон существует в одном экземпляре.

Состав полигона:
- район и три объекта: Мю, Кси, Тау;
- у каждого объекта пожарная (ПС), охранная (ОС) и диспетчерская (ДУ) часть;
- всего 183 канала по пикетам.

Идентификаторы полигона начинаются с 900000 (объекты) и 90000000 (каналы). Даже если файлы по ошибке
загрузят в боевой контур, они не пересекутся со справочником заказчика.

Пересобрать полигон: `python simulator/polygon/build_polygon.py`.

## Запуск

```bash
docker compose --profile training up -d --build
```

После запуска:
- учебный интерфейс — https://localhost/training/ (или переключатель «Учебный контур» в шапке), вход общий;
- симулятор — https://localhost/simulator/ (меню учебного контура, руководитель учений) или напрямую http://localhost:8095 с этой машины.

При старте симулятор отправляет начальное состояние всех каналов. Дальше он опрашивает числовые
датчики: метан раз в минуту, температуру раз в 2 минуты.

## Веб-интерфейс

Экран разделён на три части:
- **слева** — дерево объектов;
- **в центре** — каналы выбранного объекта с текущим режимом и последним сообщением. Над таблицей —
  охрана объекта, каскад (все каналы разом) и восстановление объекта;
- **справа** — запуск сценария на выбранном объекте с ускорением ×1…×30, ход запусков и журнал
  отправленного. По умолчанию журнал скрывает опрос показаний.

Возможности для каждого канала:
- режимы «Норма», «Тревога», «Неисправен», «Обесточен»;
- в меню «ещё»: «Отключено», «Не определено», «Нет связи», служебный код −100, дребезг и
  произвольное сырое значение;
- у числовых датчиков — точное показание (Enter) и плавный рост (↗);
- у насосов и вентиляторов — включение и выключение.

## Консоль

Внутри контейнера:

```bash
docker compose exec simulator python -m fieldsim tree
docker compose exec simulator python -m fieldsim list 900101
docker compose exec simulator python -m fieldsim scenario fire 900100 --picket 212 --speed 10
docker compose exec simulator python -m fieldsim runs
docker compose exec simulator python -m fieldsim set 90000004 alarm
docker compose exec simulator python -m fieldsim guard 900100 on
docker compose exec simulator python -m fieldsim ramp 90000048 1.4 --seconds 120
docker compose exec simulator python -m fieldsim cascade 900101 power
docker compose exec simulator python -m fieldsim restore 900100
docker compose exec simulator python -m fieldsim log -n 20
```

Из репозитория, без сервера (сценарий до завершения, вывод в консоль, файл или Kafka):

```bash
cd simulator
python -m fieldsim --sink stdout run gas 900100 --picket 212 --speed 30
python -m fieldsim --sink file:events.jsonl run fire 900200
python -m fieldsim --sink kafka --bootstrap localhost:9092 --topic smvu.training-events run flood 900300
```

По умолчанию каталогом служит полигон. На справочнике заказчика симулятор тоже работает
(`--catalog ../data`), но в боевую тему (`--topic smvu.raw-events`) писать можно только на стенде:
в эксплуатации её заполняет СМВУ.

## Сценарии

| Код | Что происходит |
|---|---|
| `fire` | Температура у пикета растёт до 52 °C, затем дым, тепловой извещатель и дым у соседнего пикета |
| `gas` | Метан растёт до 0,7 %, затем выше 1 % («Обнаружен газ»); у соседнего датчика — до 0,6 % |
| `flood` | Включаются насосы АНС, срабатывает датчик затопления, насос затоплен, пропадает питание щита |
| `intrusion` | Объект на охране, вскрыт люк, нарушитель идёт вдоль коллектора: двери и датчики движения по порядку пикетов — платформа строит маршрут |
| `temperature` | Аномальная температура без дыма: у пикета до 58 °C, у соседнего до 45 °C (теплосеть, кабели) |
| `ppr` | ППР: бригада в рабочее время по очереди проверяет 5–6 дымовых извещателей, каждый сразу сбрасывается — платформа предлагает гипотезу «ППР», а не пожар |
| `authorized` | Работы по наряду: охрана снята, дверь и движение — рабочая активность, не тревога |
| `power` | ИБП переходит на батареи, затем все каналы пожарной части разом «Обесточен»; через 4 минуты восстановление |
| `sensor` | Дребезг неисправности с учащением, служебный код −100, отказ |
| `comm` | Каналы уходят в «Неопределен», молчат 5 минут, возвращаются |
| `restore` | Всё в норму, охрана снята |

Устройства сценарий подбирает по типу и близости к пикету. Поэтому любой сценарий работает на любом
объекте, где есть нужные датчики. Паузы и плавные изменения ускоряются вместе со сценарием.

## Команды из учебного контура

С ключом `--commands` (в compose — `SIM_COMMANDS_TOPIC`) симулятор читает из Kafka команды учебных
заданий: `restore`, `scenario`, `guard`. Платформа не видит симулятор по сети, поэтому урок просит его
восстановить объект и запустить сценарий через тот же брокер. Команды видны в журнале веб-интерфейса.
Подробнее — в [docs/training.md](../docs/training.md).
