# Глоссарий

| Термин | Значение |
|---|---|
| **СМВУ** | система мониторинга, откуда приходят сигналы датчиков |
| **Канал** | один датчик или одна величина (температура, метан, состояние насоса) |
| **Пикет (ПК)** | отметка на трассе коллектора, обычно через 10 м; по пикетам строится схема |
| **Тревожное сообщение** | запись СМВУ с флагом «тревожное»; до проверки диспетчером это ещё не инцидент |
| **Авария** | угроза жизни человека: пожар, наводнение, газ, террор (проникновение), аномальная температура |
| **Инцидент** | нарушение работы систем, например потеря всей связи или питания; за ним может скрываться авария |
| **ТО / ППР** | техническое обслуживание / планово-предупредительные работы; состав задаёт РТЭКК |
| **ФРО, ФАО, ФВ, ФАНС, ФТС** | фидеры рабочего и аварийного освещения, вентиляции, насосной станции, теплосети; в скобках — что питает фидер |
| **ОЗК, ЩАП, ПУИ** | огнезадерживающий клапан, щит аварийного питания с АВР, пульт управления индикацией |
| **Сигнал** | одно сообщение канала: показание или состояние |
| **Контрольный этаж** | этаж, чей план привязан к снимку и контуру здания; планы остальных этажей привязываются к нему |
| **Контрольная точка** | одно и то же место на плане этажа и на местности; по трём и больше точкам план накладывается на снимок |
| **Невязка** | насколько точка расходится с подгонкой, в метрах; больше 2–3 м — точка поставлена неточно |
| **Маршрут нарушителя** | сработки охраны объекта в порядке времени, линией на карте |
| **Эпизод** | сигналы одного объекта и типа за 30 минут, собранные вместе |
| **Карточка (инцидент)** | то, с чем работает диспетчер: риск, причина, действия, решение |
| **Прогноз** | вероятность события на 24 часа по модели (отказ, газ, подтопление) |
| **Индикатор** | индекс 0–1 по правилам (пожар, НСД) — не вероятность |
| **Уровень риска** | низкий, средний, высокий, критический |
| **Операционный приоритет** | порядок в очереди: риск × тяжесть × критичность × срочность × доверие к данным |
| **Гипотеза причины** | почему это произошло: питание, связь, модуль датчика, работы, внешний фактор |
| **Эскалация** | подъём карточки на следующий уровень, если нет реакции в норматив |
| **Отклик** | первое действие по свободной карточке; закрепляет её за сотрудником |
| **Перехват** | руководитель забирает карточку у диспетчера |
| **Data Health** | оценка 0–100, насколько можно доверять данным канала |
| **Молчание** | канал не присылает данных дольше 6 обычных интервалов |
| **Служебный код** | технические значения (−100, даты 1970 г.), не показания |
| **Метка** | факт для обучения модели, полученный из решения диспетчера |
| **Зона ответственности** | участок района с объектами и сотрудниками; своя зона на карте выделена, чужие — серые |
| **Смежная зона** | соседняя зона: её объекты видны подробнее, сотрудников можно направить туда обычным порядком |
| **Командирование** | временная работа сотрудника в другой зоне: видит её карточки и получает её уведомления |
| **Мониторинг** | главный экран: карта зоны с объектами, датчиками, карточками и заявками |
| **Учебный контур** | отдельный стенд с полигоном и симулятором для заданий и учений |
| **Полигон** | учебные объекты и каналы в формате справочников заказчика |
| **Эмуляция (mock)** | замена внешней системы на стенде (help desk, каталог LDAP/AD, реестр оборудования) |
