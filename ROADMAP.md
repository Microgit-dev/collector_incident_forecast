# Дорожная карта

Сдача: **29.09.2026**. Статусы: `Backlog` → `In progress` → `Review` → `Done`.
Правило: каждая задача — ветка `feature/<эпик>-<кратко>` от `main`, Conventional Commits, merge после зелёных тестов.
Приоритеты: **P0** — обязательные пункты ТЗ; **P1** — сильное отличие, дешёвое на нашем каркасе;
**P2** — только после стабильного P0/P1.

## Позиционирование

> Сервис раннего выявления технических и аварийных рисков на объектах инженерных коллекторов:
> превращает поток сырых сигналов в приоритизированные риски, объясняет их, предлагает действие,
> фиксирует решение диспетчера и учится на результате.

Цикл продукта: **Предсказать → Объединить → Приоритизировать → Объяснить → Предложить действие → Получить результат → Улучшить модель.**
Главная демонстрация: «47 тревог на объекте → 1 инцидент, 3 гипотезы причины, 1 действие, 1 черновик заявки».

## После сдачи (развитие продукта)

Не входит в MVP к 29.09. Каркас (роли, команды, журнал действий, replay, отдельный контур данных) закладывается так,
чтобы эти режимы добавлялись без переделки ядра.

| Направление | Суть | Опора в каркасе |
|---|---|---|
| **Режим обучения по ролям** | Интерактивный тур по интерфейсу для каждой роли: подсказки поверх экранов, пошаговые задания («прими карточку», «выбери причину», «утверди заявку»), проверка выполнения. Работает на **учебном полигоне** — отдельном моковом наборе объектов, каналов и сигналов, изолированном от боевых данных | Роли и права, генератор событий `replay_journal`, отдельное дерево объектов под полигон |
| **Режим просмотра истории** | Исторические показания за выбранный период: объект / канал / диапазон дат, графики сырых и суточных значений, состояния и качество, наложение инцидентов и решений того времени | Parquet-архив по годам, суточная витрина, оперативная hypertable |
| **Режим учений** | Отработка всего взаимодействия по цепочке: руководитель настраивает сценарий (тип угрозы, объект, темп нарастания, отказ связи, «молчащий» диспетчер для проверки эскалации), участники работают в обычном интерфейсе с пометкой «УЧЕНИЯ», по итогам — разбор с хронологией и оценкой | Командная вертикаль, эскалация, replay, журнал действий; флаг учебного события в инциденте |
| **Отчётность и метрики сотрудников** | Время до просмотра, принятия и решения по сотруднику и команде, доля эскалаций по таймауту, качество решений (совпадение с итогом), нагрузка на смену, результаты учений и обучения; отчёты за период PDF/XLSX | Журнал действий и просмотров, события инцидента, решения с причинами |

## Сознательно не делаем

- нейросети ради нейросетей: для отказа — градиентный бустинг, для редких сценариев — правила;
- LLM в контуре принятия решений (стенд должен работать офлайн у экспертов);
- настоящую ГИС, реальные LDAP/AD и help desk — вместо них схемы и эмуляция;
- автоматическое назначение бригады без подтверждения диспетчера.
