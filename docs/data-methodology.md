# Данные и методика интерпретации

Документ фиксирует, как мы понимаем данные заказчика. Он основан на ТЗ, ответах на вопросы
участников и профилировании выгрузки. Будет дополняться в E1/E3.

## Состав выгрузки

| Файл | Содержимое | Замечания |
|---|---|---|
| `справочник_объектов_диспетчер.csv` | 95 узлов: район → 16 объектов → 78 ДП / охраняемых объектов | Основа дерева топологии и зон ответственности |
| `справочник_каналов_датчиков.csv` | 11 485 каналов, `ид_объект` связывает канал с объектом | Пикеты зашиты в названия («ТД ПК86-85», «Темп. ВШ ПК88,5») |
| `справочник_состояний.csv` | Возможные текстовые состояния по типам | Грязный: состояния у чужих типов, дубли, опечатки («35ºC1») |
| `journals/ext-journal-YYYY.csv` | Журналы 2019–2026, ~14 ГБ | `тревожное` = t/f (в примере — true/false) |

## Интерпретация значений

`значение_датчика` смешивает числа, текстовые состояния и артефакты. Движок нормализации
(`backend/apps/normalization/domain/engine.py`) приводит их к каноническим состояниям:

| Каноническое | Откуда берётся |
|---|---|
| `normal` | «Норма», «Дыма нет», число ниже порогов профиля |
| `warning` | Число выше порога предупреждения (метан ≥ 0,5 %) |
| `alarm` | «Обнаружен дым/газ/движение», «Затоплен», «Не замкнут», число выше порога тревоги (метан ≥ 1 %) |
| `fault` | «Неисправен», «Отключено устройство», служебные коды (−100, 255, −3276, −127…), значения вне допустимого диапазона, «01.01.1970 03:00:0x» |
| `power_loss` | «Обесточен», «Питание от батарей» |
| `unknown` | «Неопределен», «Не определено», нераспознанные значения |
| `event` | Рабочие события: «Включен/Выключен», «На охране/Снято с охраны», «Разговор/Вызов» |

Основание (ответы заказчика):
- формального кода отказа нет; служебные значения производителей, выход за диапазон и сбитая
  дата 1970 года трактуются как неисправность;
- газовые датчики показывают % объёма метана, порог тревоги — 1 %, 5–15 % — зона воспламенения;
- составные устройства пишут несколько аспектов одновременно (например, извещатель + домофон).
  Поэтому у состояния есть `facet` (основной, питание, охрана, температура, насосы),
  и состояние канала ведётся по каждому аспекту отдельно.

## Исключения и допущения

- **2021 год исключается** из обучения: всплеск тревог вызван переходом на новую систему мониторинга.
- **Каскады** (десятки каналов объекта одновременно переходят в «Неисправен»/«Обесточен»)
  склеиваются в один инцидент по объекту: окно группировки 30 минут, тип совпадает.
- **Журналов ОДС, решений диспетчеров, ремонтов и реестра оборудования нет.** Их заменяют:
  решения диспетчеров внутри системы (они же размечают прогнозы), эмулированный реестр
  оборудования со средними наработками на отказ из открытых источников и данные Open-Meteo.
- **Координат нет**: объекты показываются на схематической линейной карте по пикетам (GeoJSON).
