# Режим обучения по ролям

Раздел «Учебные задания» в меню. У каждой роли свои задания. Задание проходит в обычном интерфейсе,
поверх любых экранов висит панель задания:
- шаги задания;
- подсказка к текущему шагу;
- кнопка «Показать где»: переходит на нужный экран и подсвечивает элемент, остальной экран затемняется;
- таймер.

Шаг засчитывается не по кнопке «далее», а по действию в системе. Например, «взять карточку в работу»
засчитывается, когда карточка действительно закреплена за учеником.

## Где проходит

| | Рабочий контур | Учебный контур (https://localhost:8443) |
|---|---|---|
| Экскурсия по интерфейсу | да | да |
| Задания со сценариями | нет — ссылка в учебный контур | да, на полигоне |

Задания со сценариями выполняются на полигоне учебного контура (см. [simulator/README.md](../simulator/README.md)):
- своя база;
- свои объекты Мю, Кси, Тау;
- события даёт симулятор датчиков.

На работу района задания не влияют.

## Задания

| Задание | Роль | Сценарий симулятора | Что засчитывается |
|---|---|---|---|
| Знакомство с интерфейсом | все | — | Шаги подтверждает сам ученик: счётчики, схема, очередь, меню, уведомления |
| Пожар: от сигнала до решения | диспетчеры | `fire` | Карточка пожара открылась → ученик её открыл → взял в работу → решение «Выезд бригады» и «Реальное событие» → черновик заявки |
| Неисправный датчик — не событие | диспетчеры | `sensor` | Карточка → взята в работу → «Что произошло: неисправность датчика» → заявка |
| Проникновение на объект под охраной | диспетчеры | `intrusion` | Карточка НСД → взята в работу → «Направлена проверка» или выезд |
| Заявка по карточке: утвердить и передать | руководитель | `gas` | Карточка загазованности (учебный диспетчер сразу составляет черновик) → руководитель утвердил → передал в систему заявок |
| Метка из решения диспетчера | аналитик | `sensor` | Учебный диспетчер решает «Устранено дистанционно», получается метка на проверку → аналитик принял или отклонил её → нашёл канал в Data Health |
| Исполнение заявки | бригада | `flood` | Заявка на насос назначена ученику → взята в работу → выполнена |

**Ошибки.** Если решение принято, но не то, шаг не засчитывается. На панели появляется, что выбрано и
почему здесь правильно другое. Ошибка учитывается один раз на каждое неверное решение. В результате
задания видны время, ошибки и число подсказок («Показать где»).

**Вторая сторона.** Действия, которых нет в задании, выполняет учебный диспетчер `training.bot`: составляет
черновик для руководителя, принимает решение для аналитика. Войти под этой учётной записью нельзя.

## Как устроено

1. **Старт.** Урок выбирает объект полигона. Для объектного диспетчера и бригады — объект их зоны
   ответственности, для районных ролей — первый объект района по алфавиту. Урок приводит объект в
   исходное состояние: открытые карточки закрываются, незавершённые заявки отменяются.
2. **Команды симулятору.** Платформа отправляет симулятору команды «восстановить объект» и «запустить
   сценарий» через Kafka (`sim.training-commands`). Симулятор в полевом контуре, платформа не видит его
   по сети, а брокер — единственный общий канал. Команды читаются только новые, поэтому после
   перезапуска симулятор не повторяет старые уроки.
3. **Проверка шагов.** Шаги проверяются по порядку при каждом запросе панели (раз в 3 секунды). Источники:
   - журнал действий — открытие карточки (`incident.view`);
   - хронология карточки;
   - решения и их «что произошло»;
   - статусы заявок и кто их утвердил;
   - проверка меток аналитиком.
4. **Результаты.** Руководитель, аналитик и администратор видят результаты сотрудников своей зоны,
   остальные — свои.

Если два ученика одновременно проходят задания на одном объекте, их сценарии мешают друг другу. Для
группового обучения ученикам назначают разные объекты полигона — через зоны ответственности.

## API

| Метод | Что делает |
|---|---|
| `GET /api/v1/training/lessons/` | Задания для ролей пользователя, доступность в этом контуре, лучший результат |
| `POST /api/v1/training/sessions/` `{"lesson": "dispatcher-fire"}` | Начать задание; текущее прерывается |
| `GET /api/v1/training/sessions/current/` | Текущее задание; шаги проверяются при каждом запросе |
| `POST /api/v1/training/sessions/{id}/confirm/` `{"step": "find"}` | Подтвердить шаг без проверки (экскурсия) |
| `POST /api/v1/training/sessions/{id}/hint/` | Учесть подсказку |
| `POST /api/v1/training/sessions/{id}/abandon/` | Прервать; симулятор возвращает объект в норму |
| `GET /api/v1/training/sessions/` | Результаты: свои или сотрудников зоны |
