# Отчёт по безопасности системы

Проверка всей системы: рабочий и учебный контуры, симулятор, инфраструктура docker compose,
зависимости. Дата — 26.09.2026, версия — ветка `main` после E18. Проверки выполнены на развёрнутом
стенде и в коде. Все инструменты и скрипты можно повторить (раздел «Как повторить»).

## Итог

- **Найдено 14 замечаний:**
  - 2 высокого уровня;
  - 5 среднего;
  - 2 низкого;
  - 5 информационных.
- **Исправлено 7.** Все высокие и средние, кроме паролей стенда, и одно низкое. Каждое исправление
  проверено повторно на стенде и закреплено автотестами.
- **Остальные 7** относятся к конфигурации стенда. Для ввода в эксплуатацию они вынесены в чек-лист.
- **Разграничение доступа выдержало пробу.** 41 попытка обойти роли и зоны на живом API, все
  отклонены. Карточки чужой зоны недоступны ни на чтение, ни на действие.
- **Уязвимых зависимостей нет.** Проверено 81 пакет Python (pip-audit) и 185 пакетов интерфейса
  (npm audit).

## Модель угроз

| Нарушитель | Что может попытаться | Чем закрыто |
|---|---|---|
| Сотрудник с учётной записью | увидеть или изменить данные чужой зоны, действовать сверх роли (утвердить заявку, перехватить карточку) | роли (права Django) и фильтр зоны в каждом запросе; объекты вне зоны отдают 404 |
| Посторонний в сети предприятия | подобрать пароль, прочитать или подменить поток событий датчиков, открыть служебные интерфейсы | блокировка входа, TLS, наружу опубликован только Caddy, служебные UI — только на localhost |
| Внедрение кода через данные (XSS) | украсть токен из браузера | CSP без внешних и встроенных скриптов, Markdown без HTML, короткий access-токен |
| Утечка журналов или резервных копий | войти по токену из журнала, прочитать ПДн | токенов в адресах нет; пароли только хешами; копии — внутри контура |
| Ошибка развёртывания | запуск с ключами и паролями по умолчанию | системная проверка: в эксплуатации ключ по умолчанию не даст запуститься |

## Как устроена защита

- **Периметр.** Наружу публикуется только Caddy (80 → 443, 443, 8443 — учебный контур). HTTP
  перенаправляется на HTTPS, TLS 1.2+, HSTS. База, Redis, Kafka, LDAP, help desk, Prometheus и
  экспортеры доступны только во внутренней сети docker. Kafka UI и симулятор слушают только
  `127.0.0.1`. Симулятор живёт в отдельной сети `field` и видит только Kafka.
- **Контуры.** Учебный контур — отдельные база, Redis, тема Kafka и help desk на другом порту
  (другой origin), поэтому вход и токены контуров не смешиваются.
- **Аутентификация.**
  - LDAP/AD или локальные учётные записи; пароли — только хешем PBKDF2.
  - API — JWT: access 30 минут, refresh 7 суток с ротацией и чёрным списком; выход отзывает refresh.
  - WebSocket — токен в заголовке `Sec-WebSocket-Protocol`, не в адресе.
  - Админка — сессия с cookie `Secure`, `HttpOnly`.
- **Защита от подбора.** После 5 неудачных попыток учётная запись блокируется на 15 минут.
  Блокировка действует для всех способов входа: API, админка, LDAP. Регистр логина её не обходит.
  Блокировка пишется в журнал действий.
- **Авторизация.** 7 ролей (группы и права Django) и зона ответственности. Права проверяет бэкенд
  в каждом запросе, интерфейс лишь прячет недоступное. Объекты вне зоны отфильтрованы запросом,
  API отвечает 404 и не раскрывает, что объект существует. Перехват карточки — только у руководителя,
  учения — только у руководителя и администратора, вики — правка только из админки.
- **Заголовки.** На интерфейсе:
  - `Content-Security-Policy`: скрипты только свои, `frame-ancestors 'none'`, `object-src 'none'`;
  - `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy`, `Permissions-Policy` (камера, микрофон, геолокация, платежи запрещены);
  - заголовок `Server` скрыт.
- **Журналирование.**
  - Каждое изменяющее запрос и бизнес-событие (решение, перехват, учения, выгрузка, вход) пишется
    с пользователем, IP и временем.
  - Просмотры карточек фиксируются.
  - Изменения записей (инциденты, решения, политики эскалации, статьи вики) — в django-auditlog.
- **Данные.** Интеграции с системами заказчика — только на чтение (кроме передачи утверждённой
  заявки). Путь к файлу при импорте из каталога данных проверяется: выйти за каталог нельзя.
  Markdown вики отображается без исполнения HTML.
- **Контейнеры.** Бэкенд работает от непривилегированного пользователя `app` (uid 1000).
- **Резервные копии.** Ежедневный `pg_dump` с ротацией: 7 дневных и 4 недельных копии.
  Восстановление проверено (глава «Резервное копирование»).

**Ложные срабатывания bandit:**
- `sha1` и `md5` считают ключ кеша выборки и разброс темпа в эмуляции смен, это не защита.
  Помечены `usedforsecurity=False`.
- Четыре «SQL из строк»: в запрос подставляются только имена колонок из констант модуля или из кадра,
  собранного кодом. Пользовательского ввода там нет. Помечены `nosec` с причиной; одно многострочное
  bandit всё равно показывает.

## Чек-лист ввода в эксплуатацию

1. `SECRET_KEY` — случайный, 64+ символа:
   `python -c "import secrets; print(secrets.token_urlsafe(64))"`.
2. `DEMO_USERS=false`. Сменить пароли администратора, Grafana, PostgreSQL, LDAP; `DEBUG=false`.
3. `manage.py check --deploy` без ошибок `collector.S001`.
4. Имя сервера и сертификат — в `.env` (`SITE_ADDRESS`, `TLS`); `ALLOWED_HOSTS`,
   `CSRF_TRUSTED_ORIGINS` и адреса контуров — на это имя. Порядок — в `docs/deployment.md`.
5. LDAP заказчика — через `ldaps://` или StartTLS; сервисная учётка только на чтение.
6. Kafka UI и симулятор в эксплуатацию не выносить: они остаются на `127.0.0.1` или выключаются.
7. Резервные копии — на отдельное хранилище, с шифрованием; раз в квартал — пробное восстановление.
8. Журнал действий хранить по регламенту заказчика; доступ к нему — у руководителя и аналитика
   (право `audit.view_actionlog`).
9. Сетевой доступ к 443/8443 — только из сети предприятия или через VPN.
10. Подложка карты и Overpass — собственные серверы внутри сети (`MAP_STYLE_LIGHT/DARK`,
    `MAP_TILES_ORIGIN`, `OVERPASS_URL`) или пустые значения: карта без подложки, контуры обводятся
    вручную.
11. Внешний слушатель Kafka (9094) — только для адреса шлюза СМВУ; при требовании — TLS/SASL.

## Как повторить

```bash
# Конфигурация Django и свои проверки безопасности
docker compose exec backend python manage.py check --deploy
# Статический анализ и зависимости
cd backend && uvx bandit -q -r apps config -x tests,migrations -ll
uv export --no-hashes --no-dev > /tmp/req.txt && uvx pip-audit -r /tmp/req.txt --no-deps --disable-pip
cd ../frontend && npm audit --omit=dev
# Заголовки
curl -skI https://localhost/
# Автотесты безопасности: блокировка, ротация и отзыв токенов, схема API, WebSocket, проверки ключа
cd ../backend && uv run pytest apps/accounts/tests/test_security.py apps/notifications/tests
```
